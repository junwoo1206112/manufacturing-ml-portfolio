# 면접 대비 자료

## 프로젝트 소개 (1분 버전)

"Smart Manufacturing Simulation Portfolio는 제조 공정 데이터를 분석하고 예측하는 AI 시스템입니다.

핵심 기능은 5가지입니다:
1. **품질 예측**: 센서 데이터(온도, 압력, 진동) 기반 불량 예측
2. **SHAP 해석**: 개별 예측에 대한 특성 기여도 분석
3. **이상 탐지 + 드리프트 감지**: 비정상 패턴 및 분포 변화 모니터링
4. **예측 정비**: 설비 건강 점수 및 잔여 수명(RUL) 추정
5. **실시간 대시보드**: Flask + Chart.js 기반 모니터링

기술적으로 Python, Scikit-learn, Flask를 사용했고, RandomForest에 class_weight balanced와 validation-set 기반 threshold tuning을 적용하여 불량 클래스 F1-score 약 0.59, AUC-ROC 약 0.85 수준의 성능을 달성했습니다."

## 프로젝트 소개 (3분 버전)

"이 프로젝트는 제조 공정 데이터 분석 및 예측 AI 포트폴리오입니다.

**문제 인식:**
제조 공정에서 불량이 발생하면 비용이 크게 발생합니다. 사전에 불량을 예측하고 예방하는 것이 중요합니다.

**해결책:**
1. 물리적 기반 시뮬레이션으로 현실적인 제조 데이터를 생성
2. 머신러닝 모델로 불량 예측 + SHAP으로 예측 설명
3. KS test + PSI로 데이터 드리프트 감지
4. Flask 기반 대시보드로 실시간 모니터링

**기술적 특징:**
- **데이터**: 온도·압력·진동·습도 센서 데이터에 물리적 패턴(일일 주기, 피로 누적) 반영
- **모델**: RandomForest + threshold tuning, SHAP TreeExplainer로 해석성 확보
- **드리프트 감지**: KS test(분포 형태) + PSI(이산화 비교) 이중 검증
- **예지보전**: 로그 정규 분포 기반 RUL 추정, 설비 건강 점수 산출
- **코드 품질**: 전 모듈 타입 힌트, 구조화된 logging, 풍부한 모델 메타데이터(schema v2)
- **인프라**: Docker containerization, GitHub Actions CI

**성과:**
- 불량 클래스 F1-score ~0.59, AUC-ROC ~0.85, AUC-PR ~0.66
- SHAP 특성 중요도 시각화 (temperature, vibration가 주요 변수)
- 드리프트 감지로 온도 +2°C shift와 진동 ×1.3 scale 변화 탐지 성공
- 클래스 불균형, 임계값 최적화, 드리프트 등 실무 이슈 명시적 처리

## 기술적 의사결정 질문

### Q: 왜 RandomForest를 선택했나요?

A: RandomForest를 선택한 이유는 3가지입니다:
1. **과적합 방지**: 트리 앙서블이 과적합에 강합니다
2. **해석 용이**: 특성 중요도 + SHAP TreeExplainer 호환
3. **성능**: 타 모델 대비 빠르게 준수한 성능 달성

추가로 GradientBoosting과 비교 실험을 통해 최적 모델을 선정했습니다.

### Q: 데이터 불균형은 어떻게 해결했나요?

A: 제조 데이터는 불량률이 낮아(보통 5~15%) 클래스 불균형이 발생합니다.
저희는 다음 방법을 적용했습니다:
1. **Stratified Split**: 학습/검증/테스트 분할 시 클래스 비율 유지
2. **class_weight='balanced'**: 소수 클래스에 자동 가중치 부여
3. **Threshold Tuning**: 검증 세트에서 F1-score를 최대화하는 확률 임계값 선택
4. **AUC-PR**: 불균형 데이터에 적합한 평가 지표 활용

### Q: ML/DL 프레임워크 대신 Scikit-learn을 선택한 이유는?

A: 이 프로젝트의 목적은 제조 도메인 지식과 ML 파이프라인 설계 역량을 보여주는 것입니다. Scikit-learn은 RandomForest, Isolation Forest, GridSearch 등 다양한 알고리즘을 통일된 API로 제공하며, SHAP과의 호환성도 우수합니다. 실제로 DL이 항상 정답은 아니며, 제조 현장에서는 해석력과 안정성이 더 중요할 때가 많습니다.

### Q: SHAP을 사용한 이유는?

A: 불량 예측에서 "왜 이 제품이 불량으로 분류되었는가?"를 설명할 수 있어야 합니다. SHAP TreeExplainer는 각 특성의 기여도를 Shapley value 기반으로 정량화하여, 면접관에게 모델의 의사결정 과정을 투명하게 보여줄 수 있습니다.

### Q: 데이터 드리프트 감지는 왜 필요한가요?

A: 실제 제조 현장에서는 센서 노후화, 원자재 변경, 계절 변화 등으로 데이터 분포가 시간에 따라 변합니다. 학습 시점의 분포와 운영 시점의 분포가 다르면 모델 성능이 저하됩니다. KS test로 분포 형태 차이를, PSI로 이산화된 분포 변화를 각각 감지하여 조기 경보를 제공합니다.

### Q: Docker는 왜 사용했나요?

A: 면접관이 "이 프로젝트를 제 컴퓨터에서 실행해보려면 어떻게 하나요?"라고 물었을 때, `docker compose up` 한 줄로 전체 시스템이 실행되는 것은 강력한 신뢰를 줍니다. 또한 GitHub Actions CI와 결합하여 push마다 테스트가 자동 실행되는 파이프라인을 구축했습니다.

### Q: 실제 서비스로 확장하려면?

A: 다음 단계가 필요합니다:
1. **실시간 데이터 수집**: MQTT나 Kafka를 통한 센서 데이터 스트리밍
2. **모델 배포 확장**: Kubernetes로 스케일링, API 게이트웨이 도입
3. **MLOps**: 주기적인 재학습 파이프라인, 모델 레지스트리
4. **보안**: API 인증/인가, 데이터 암호화
5. **모니터링 고도화**: Grafana + Prometheus 기반 성능 모니터링

### Q: 가장 어려웠던 점은?

A: **데이터 시뮬레이션의 현실화**가 가장 어려웠습니다.
랜덤 데이터는 실제 공정과 다릅니다. 그래서:
1. 온도의 일일 주기 패턴을 도입하고
2. 진동의 설비 피로 누적을 시뮬레이션했으며
3. 공정별(전자부품, 기계부품, 소비재)로 상이한 센서 범위를 설정했습니다.

두 번째 과제는 **클래스 불균형**이었습니다. 초기 모델의 불량 F1이 0에 가까웠으나, Stratified Split과 threshold tuning을 도입하면서 F1 ~0.59까지 개선했습니다.

### Q: 성과는 어떻게 측정했나요?

A: 불균형 데이터에서는 accuracy만으로 성능을 판단할 수 없어 다음 지표를 함께 사용했습니다:
1. **Precision/Recall/F1**: 정상/불량 클래스별 및 매크로 평균
2. **AUC-ROC**: 모델의 전반적인 분류 성능 (현재 ~0.85)
3. **AUC-PR**: 불균형 데이터에서의 신뢰도 평가 (현재 ~0.66)
4. **Accuracy**: 참고 지표로만 활용 (현재 ~0.82)

제조 현장에서는 Recall(재현율)이 중요합니다. 불량을 놓치면 큰 비용이 발생하기 때문입니다. threshold tuning 시 F1을 기본 메트릭으로 사용하되, trade-off를 설명할 수 있어야 합니다.
