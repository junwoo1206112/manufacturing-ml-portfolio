# 아키텍처

## 시스템 개요

Smart Manufacturing Simulation Portfolio는 제조 공정 데이터를 분석하고 예측하는 시스템입니다.

## 크로스커팅 관심사

- **로깅**: `src/logging_config.py`의 `setup_logging()`으로 모든 모듈이 구조화된 로깅 사용
- **설정**: 모든 모듈이 `src.config` 모듈을 통해 설정 주입 (config-driven architecture)
- **타입 안전성**: 모든 공개 함수/메서드에 타입 힌트 적용 (`from __future__ import annotations`)

## 데이터 흐름

1. **데이터 생성**: `DataGenerator`가 물리적 기반 시뮬레이션으로 제조 데이터 생성 (온도 일일 주기, 진동 피로 누적)
2. **데이터 검증**: `DataValidator`가 데이터 품질 검증 (스키마, 결측치, 범위)
3. **데이터 분석**: `DataAnalyzer`가 불량률, 통계 분석
4. **데이터 전처리**: `DataPipeline`이 인코딩, 스케일링, 통계 특성 엔지니어링 수행
5. **모델 학습 + SHAP**: `QualityPredictor`가 불량 예측 모델 학습 후 `explain_prediction()`으로 SHAP 특성 기여도 산출
6. **모델 저장**: `ModelManager`가 모델 + 풍부한 메타데이터(threshold, feature_importance, class_distribution 등) 저장
7. **이상 탐지 + 예지보전**: `AnomalyDetector` + `PredictiveMaintenance`로 설비 상태 및 RUL 산출
8. **드리프트 감지**: `DriftDetector`가 KS test + PSI로 참조 vs 실시간 분포 비교
9. **시각화**: `Visualizer`가 4종 PNG 차트 생성
10. **대시보드**: Flask + Chart.js로 9개 REST API 엔드포인트 제공

## 주요 설계 의사결정

### 설정은 어떻게 관리하는가?
- `config/config.yaml`에 데이터, 라인, 임계값, ML, 대시보드, 드리프트 설정을 중앙 집중화
- `src/config.py`가 YAML을 로드하고 기본값과 deep-merge하여 런타임에 제공
- 모든 모듈은 `from src.config import ...`로 설정 사용

### 예측 정비는 어떻게 동작하는가?
- `config/equipment.json`의 센서값과 고장 이력을 로드
- 센서 임계값 기반으로 건강 점수 및 상태 산정
- 고장 간격 로그 정규 분포를 이용해 잔여 수명(RUL)과 신뢰도 점수 추정
- 이력이 없는 설비는 보수적인 기본값과 낮은 신뢰도 사용

### 왜 RandomForest를 기본으로 선택했는가?
- 과적합 방지에 강함
- 특성 중요도 제공
- 비선형 관계 포착 가능
- SHAP TreeExplainer와 호환

### 클래스 불균형은 어떻게 처리하는가?
- `class_weight='balanced'`로 소수 클래스에 가중치 부여
- 검증 세트에서 F1-score를 최대화하는 확률 임계값 자동 선정
- AUC-PR 등 불균형 지표를 활용한 성능 평가

### 데이터 드리프트는 어떻게 감지하는가?
- **KS test**: 각 특성별 분포 차이의 통계적 유의성 검정
- **PSI**: 업계 표준 Population Stability Index로 이산화된 분포 비교
- 이중 검증으로 위양성률 최소화

### 왜 앙서블 방법론을 제공하는가?
- VotingClassifier를 `model_type='ensemble'`로 선택 가능
- 단일 모델의 한계 보완 및 예측 안정성 향상
- 현재 메인 파이프라인은 해석력과 훈련 속도가 우수한 RandomForest를 기본으로 사용

### 왜 Flask를 선택했는가?
- 가벼움
- 학습 곡선 완만
- 확장 용이
- Python 생태계와 잘 통합
